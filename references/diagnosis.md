# 诊断说明:如何判断「单连接限速」并决定分片策略

## 为什么下载会慢

一个直连下载慢,瓶颈通常在三者之一:

1. **你本地网络** — 但那是全局慢(看视频/其他站也慢)。本技能不处理。
2. **服务器按整 IP / 上行限速** — 无论开几条连接,总吞吐都被天花板卡死。分片无效。
3. **服务器按单连接限速** — 每个 TCP 连接被限速到很低(典型 ~10 KB/s),但
   不限制你开多少条连接。开 N 条 → 总吞吐约 N × 单连接限速。分片有效 ✅

类型 3 在小厂商自建服务器、无 CDN 的单机 nginx 上极常见。

## 用探针区分类型 2 与类型 3

`probe_speed.sh` 做两件事:

- 单连接 12 秒下载,得 `单连接吞吐`(字节/s)。
- 6 路并行 10 秒下载,得 `并行吞吐`(字节/s)。

判读阈值(经验值):

| 现象 | 结论 | 对策 |
|---|---|---|
| 单连接 ~10KB/s,并行 ~×N 更快 | 单连接限速 | `parallel_download.sh` 分片 |
| 单连接慢,并行吞吐几乎不涨 | 整 IP/上行限速 | 分片无效;换 CDN、镜像、迅雷 P2P、或换网络(云主机中转) |

> 注意:探针用的 10 秒窗口较短,偶发波动可能误导。若结论临界,可手动
> 复测一次或观察 `单连接吞吐 × 分片数` 与 `并行吞吐` 的差距。

## 服务端线索(用 `curl -sI <URL>` 看)

- `Accept-Ranges: bytes` 存在 → 可用 Range 分片(本技能核心前提)。
- `Server: nginx` + 单 IP + 无 `via`/CDN 头 → 大概率是单机源站,限速概率高。
- 文件大(>20MB)+ 单连接极慢 → 分片收益最明显。

## 分片数怎么选

脚本默认 16 片。经验:

- 单连接限速越低(如 5 KB/s),片数越多收益越大(24–32)。
- 但片数过多可能触发服务端对单 IP 并发连接数的拒绝。若部分分片反复
  `CHUNK_FAIL`,先降到 8–12 片重试。
- 每片内部已带 `--speed-limit 4000 --speed-time 8` + 最多 10 次重试,
  单条僵死连接会被自动放弃重连,不会整体挂死。

## 常见失败与处理

- **合并后字节数不符** → 某片仍不完整。重跑脚本;若仍失败,降片数。
- **部分分片 CHUNK_FAIL** → 服务端并发限制或该区间偶发断开。降片数或加
  `--retry` 次数。
- **环境无 `seq`/`tee`/`xxd`、`/tmp` 不存在** → 脚本已规避,写临时片到
  当前目录并用 C 风格循环。
- **`rm` 报 Device or resource busy** → Windows Defender 锁文件,忽略即可,
  不影响已合并产物。
